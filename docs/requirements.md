# 사내 AI Agent Harness 요구사항

기준일은 2026년 11월 13일이다. 사용자와 합의한 요구사항을 기록한다. 구현 설계와 검증 계획은 [architecture.md](architecture.md), [implementation-plan.md](implementation-plan.md)에 둔다. 아직 선택하지 않은 세부 설정을 확정된 요구사항으로 취급하지 않는다.

## 제품 목적과 환경

메일·Confluence·메신저에서 업무 맥락을 파악하고, 모델 개발·학습·Android 개발에 활용한 뒤, 결과를 문서·wiki·메일·메신저 초안으로 연결한다. 궁극적으로 자율적으로 자기 기능을 개선하는 harness를 지향한다.

- 첫 버전은 1인용이다. 향후 약 20명까지 배포할 가능성은 있지만 공유 서버나 다중 사용자 운영은 첫 버전의 전제가 아니다.
- 사용자와 AI agent 중심으로 개발하며 중간 빌드를 실제로 사용해 개선한다.
- Windows를 최우선으로 지원하고 WSL 없이 동작한다. Linux는 공통 기능의 호환성을 유지한다.
- 기준 PC는 RAM 64GB, i9-14900K, RTX 3050 OEM이다. VRAM 용량은 미확인이다.
- 프로젝트 약 5개를 동시에 사용하고 에이전트는 최대 10개까지 운영한다.
- 디스크 여유 공간은 약 100GB로 이해한다. 저장소 자체의 크기는 별도 확인 대상이다.
- 외부 에디터 의존을 지양하고 이 제품을 주 에디터로 사용한다.

## 기술 방향

- DeepSeek Harness의 구조를 참고하되 Cordis만 사용해 자체 harness를 구현한다. DSH 포크나 DSH 플러그인 바이너리 호환성은 요구하지 않았다.
- Harness는 TypeScript, Desktop의 렌더링과 UI 로직은 Rust 네이티브로 구현한다.
- GUI와 harness는 별도 프로세스로 구성한다.
- GPUI와 GPUI Kit를 우선 검증하고 결과에 따라 채택한다. 최종 채택과 정확한 버전은 미정이다.
- Node.js와 Python은 앱에 포함하지 않는다. 설치된 런타임 경로와 호환성을 확인한다.
- 언어 서버는 앱이 관리하는 별도 패키지로 제공한다. 기존 설치 재사용, 사내 mirror, 오프라인 패키지, 버전 고정과 복원을 지원한다.
- 사내 mirror·proxy·registry가 있다. 구체적인 주소와 인증 방식은 배포 환경 설정으로 받는다.
- 사내 CA 인증서와 인증 없는 proxy를 사용한다. 사내 네트워크 설정 재사용을 기본으로 한다.
- 자체 제작 실행 파일 사용이 가능하고 앱의 자격증명 저장을 허용한다. 관리자 권한 없이 설치해야 하는지는 아직 미확인이다.
- 자격증명은 운영체제 자격증명 API 대신 설정 파일에 필요한 파일 경로를 지정하는 간단한 방식으로 관리한다. SSH 설정·키와 CA 등도 경로 설정을 재사용한다.
- 설정은 YAML 파일과 설정 화면을 함께 제공한다. 사용자 기본 설정 → 프로젝트 설정 → 세션 선택값 순으로 적용하고 값의 출처를 표시한다. UI 변경은 같은 파일에 저장하고 직접 편집은 검증 후 반영한다. 잘못된 설정은 오류 위치를 표시하며 마지막 정상 설정을 유지한다.
- 앱 업데이트는 수동도 허용한다.
- 개발 작업의 Python은 uv를 사용하고, Python 바이너리와 uv 캐시는 로컬 작업공간에 둔다. PowerShell 출력은 UTF-8로 설정한다.

## 자기 개선

장기 목표는 명시적 요청, 업무 중 필요 발견, 작업 후 회고, 유휴 시간 탐색을 모두 지원하는 것이다. 첫 버전의 시작 조건은 명시적 요청이다.

우선순위는 사용자·프로젝트 지식 활용, agent loop 판단 품질, 실패 원인 분석과 복구 순서다.

절차는 개선 요청 → 구체적인 변경 제안 → 사용자 동의 → 후보 수정·검증 → 허용 범위에서 적용 → 시험 사용·사용자 평가다. 제안 동의 전에 수정 작업을 시작하지 않는다. 원본 데이터와 사용자가 제한한 대상을 제외하고 모든 구성에 대한 개선안을 제안할 수 있다.

- 개선 제안에 변경 대상·범위·검증·적용 대상·실패 대응을 포함한다. 사용자가 동의하면 명시된 범위에서 수정·검증·적용까지 수행하고 범위를 벗어나면 새 제안을 요청한다.
- 권한 확대·승인 규칙 변경·저장 형식 변경은 제안에 명시한다. 제안에 포함되지 않은 권한을 일반 기능 수정에 묻어 확대하지 않는다.
- 품질 향상의 최종 판단은 사용자 평가다. 시험 사용 후 평가, 대화 피드백, 별도 평가 화면을 제공한다.
- 피드백이 없으면 평가 미정이다. 자동 테스트 통과를 품질 향상으로 간주하지 않는다.
- 원본 메일·wiki·Confluence·Office 파일과 원본 대화·도구 실행 기록을 자기 개선 목적으로 변경하지 않는다. 일반 업무 지시에 따른 원본 수정은 해당 업무 권한을 따른다.

## Hot reload와 작업 유지

- Agent loop, 모델 어댑터, tools, context 전략, 스케줄러, 정책 등 harness 기능을 교체 대상으로 한다.
- 세션·저장소 구현 교체에는 데이터와 상태 호환성 검증이 필요하다.
- Cordis 자체, JS 런타임, 시작·감독 부분과 Rust 실행 파일은 상태 보존을 고려한 재시작을 허용한다.
- 새 작업은 새 core 버전을 사용한다. 기존 작업은 사용하던 버전을 유지한다.
- 현재 문제를 해결하기 위한 개선은 선택적으로 현재 작업에 적용한다. 전환 시점과 버전을 기록한다.
- 구버전·신버전의 일시적 공존으로 인한 메모리 증가를 허용한다.
- 안전 지점은 현재 모델 응답 처리, 해당 단계의 도구 호출, 결과·상태 저장을 마치고 다음 모델 요청을 시작하기 전이다.
- 교체를 위해 장기 빌드·GPU 작업을 중단하지 않는다. 입력 대기열과 질문·승인 대기를 유지한다.
- 승인 대상이 바뀌면 이전 승인을 그대로 재사용하지 않는다.
- 안전 지점을 기본 120초 안에 얻지 못하면 현재 작업 전환을 취소하고 다음 작업부터 적용한다. 대기 시간은 설정 가능하다.
- 초기화 실패 시 기존 버전을 유지한다. 적용 후 외부 변경이 발생했다면 코드 복원과 외부 변경 취소를 구분한다.

## 실행과 모델

- OpenAI 호환 API, OpenAI Responses API, Anthropic Messages API를 지원한다. OpenAI 호환 범위는 Chat Completions를 우선 가정하며 실제 endpoint로 확인한다.
- 역할별 모델을 설정하고 미지정 역할에는 주 모델을 사용한다. 사용자가 지정한 대체 모델 경로를 지원한다.
- 에이전트 최대 10개는 하위 에이전트·자기 개선 작업을 포함한다. 대기 중인 부모가 자식 실행 슬롯을 막지 않도록 한다.
- 모델 요청은 기본 동시 3개이며 설정 가능하다. 장기 외부 작업은 에이전트 슬롯과 별도로 관리한다.
- 프로젝트 간·프로젝트 내 병렬 작업과 하위 에이전트를 허용한다.
- 작업별 Git worktree를 로컬·원격에서 사용한다. 현재 체크아웃 사용도 선택 가능하며 공유 파일 수정 충돌을 조정한다.
- 실행 중 입력은 현재 요청 종료 후 처리하는 대기열 방식이 기본이다. 사용자가 다음 안전 지점에서 현재 작업에 반영하도록 선택할 수 있다.
- 창을 닫아도 백그라운드 작업을 유지하고 재접속한다. 프로세스 전체 종료 동작은 별도 설계한다.
- 모델·네트워크의 일시적 오류는 간격을 두고 추가 재시도 최대 2회를 기본으로 한다.
- 빌드·테스트 수정 루프의 횟수·시간 한도는 각각 선택 설정이다.
- 외부 상태를 바꾸는 작업은 성공 여부를 확인한 뒤 재시도한다. 확인 불가 시 임의 반복하지 않는다.
- 사용량은 표시만 하는 것이 기본이다. 설정된 한도에 도달하면 작업을 중단한다. 이미 실행된 외부 작업의 취소·유지 규칙은 구분해야 한다.
- 요청 수·토큰·시간을 표시하고 요금 미등록 endpoint의 비용을 임의로 계산하지 않는다.

## Context와 기억

- 원본 대화·도구 결과를 보존한다. 목표·제약·결정·미완료 작업·근거를 중심으로 모델 context를 구성한다.
- 긴 결과는 필요한 부분과 원문 참조를 제공한다. 자동 압축은 상태만 표시하고 압축 결과와 실제 모델 요청 context를 기록한다.
- 정해진 정책에 따른 자동 압축은 별도 승인 없이 수행한다. 압축 전략 자체의 수정은 자기 개선 절차를 따른다.
- 기억은 harness 화면에서 관리한다. Obsidian은 일반 노트 공간이다.
- 명시적 사용자 선호·규칙, 확인한 프로젝트 사실, 결정, 실패·해결 과정, 미완료 작업을 성격별로 자동 기록한다.
- 추론한 성향·규칙은 후보 기억으로 구분한다. 에이전트 제안과 사용자 확정 결정을 혼동하지 않는다.
- 기억에는 출처·확인 시점·적용 범위를 부착하고 확인·수정·삭제 기능과 변경 목록을 제공한다.
- 경험을 기록하는 행위와 행동 규칙을 바꾸는 행위를 구분한다.

## 업무 자료와 프로젝트 연결

- 구조화된 메타데이터는 SQLite, 원문·첨부·큰 로그·context 기록은 별도 파일 저장소와 참조로 관리한다.
- 키워드와 의미 검색을 함께 지원한다. 임베딩을 사용할 수 없으면 키워드 검색을 유지한다.
- 임베딩 모델은 google/embeddinggemma-2를 로컬 Python worker에서 실행한다. 설정에 모델 디렉토리를 지정하고 GPU 사용 가능 여부를 확인해 사용하며 CPU 실행도 지원한다.
- 의미 검색은 텍스트·코드·이미지까지 포함하고 768차원으로 시작한다. 음성·영상 색인은 이후 확장한다. 검색 결과에서 원문·페이지·슬라이드로 이동할 수 있게 한다.
- 사용자 검색을 대량 색인보다 우선 처리하고 대량 색인의 일시정지·재개를 지원한다. 모델·설정 변경 시 색인 호환성을 확인한다. DRM 문서의 이미지 추출 가능 여부는 실제 환경에서 검증한다.
- 요청 시 검색과 지정 범위 주기적 수집을 지원한다. Outlook은 최근 3개월을 최초 수집하고 과거는 요청 시 탐색한다.
- Outlook 지정 범위는 앱 실행 중 5분 간격, Confluence 지정 범위는 60분 간격 확인을 기본으로 한다. 화면 제어가 필요하면 대기한다. 메신저는 요청 시 수집을 우선하고 대화방별 주기 수집은 명시적으로 설정한다.
- 메일은 클래식 Outlook에서 수집한다. 보낸 메일도 포함하며 웹메일 수집 경로는 향후 확장 가능하게 한다.
- 수신·발신 메시지 원문은 독립 보존하고 대화 관계로 묶는다. 반복 인용은 파생 검색·요약에서 중복을 줄인다.
- 대화 일부만 수집되면 표시한다. 제목만으로 확정 병합하지 않는다. 스레드 하나를 여러 작업에 연결할 수 있다.
- 첨부 목록·크기·유형·출처를 수집한다. 프로젝트 관련 일반 문서·이미지는 기본 파일당 20MB 이하를 자동 보관하고 나머지는 필요할 때 가져온다. 전체 50GB 한도가 우선하며 개별 한도는 설정 가능하다.
- 중요한 지정 스레드는 첨부까지 보관한다. 지연 다운로드 항목은 완전한 아카이브로 표시하지 않는다.
- 파일 내용의 중복 저장을 줄이되 모든 출처 연결을 유지한다. 같은 이름의 다른 파일은 별도 버전이다.
- 첨부 미다운로드·미분석·접근 불가 상태를 구분한다. DRM 파일의 보호 형식을 유지한다.
- 수집 사본·첨부·추출 텍스트·검색 색인·자료 보관 버전에 50GB 한도를 적용한다.
- 개발 저장소·모델·학습 데이터·빌드 결과·기존 vault와 Office 파일·대화 실행 기록은 이 50GB와 별도로 집계한다.
- 재생성 가능한 캐시부터 정리하고 부족하면 대용량 수집을 보류해 정리를 제안한다. 보관한 원본을 조용히 삭제하지 않는다.
- 프로젝트와 독립된 공유 자산, 자산 버전, 프로젝트별 사용 관계, 실행 결과, 근거를 연결한다.
- 모델 업데이트가 연결된 프로젝트의 사용 버전을 자동 변경하지 않는다. 평가에는 모델·데이터·기기·실행 조건을 남긴다.
- 현재 프로젝트 → 연결된 자산 → 관련 프로젝트 순으로 검색 범위를 확장한다. 새 연결은 제안하고 다른 프로젝트 출처를 표시한다.
- Obsidian 사용자의 편집·이동·삭제를 반영하되 원문과 사용자 해석을 구분한다. 과거 작업 근거의 보존은 활성 기억과 구분한다.
- endpoint별 자료 전달 허용 범위를 설정할 수 있다. 초기 기본값은 모두 전달 가능이다.
- 백업·이동은 수동 내보내기·가져오기로 시작한다. 전체 또는 프로젝트별 설정·기억·대화·작업 기록을 기본 대상으로 하고 원문·첨부 포함 여부와 용량을 표시한다. 자동 정기 백업은 첫 버전에 필요하지 않다.
- 원격 모델·데이터셋은 기본 내보내기에 위치·식별 정보를 담고 파일 본체 포함은 별도 선택한다. 저장 형식 변경 전 복구 가능한 상태를 확보한다.

## 업무 연동과 권한

| 대상 | 요구 동작 |
| --- | --- |
| 웹 | Chrome 기존 사용자 환경·전용 환경 모두 고려. 주기적 재로그인·MFA 시 사용자 개입 |
| Confluence | 조회 API도 사용 불가. 웹 UI 접근과 확인 후 게시 |
| 메일 | 수집은 Outlook 우선, 작성은 웹메일 초안. 발송 권한은 별도 미정 |
| 사내 메신저 | 데스크톱 UI 접근. UI 요소 접근 가능성 검증. 초안은 harness에 표시 |
| Obsidian | 지정 폴더에 새 노트 작성 |
| Office | DRM 환경, win32com 사용. 기존 파일 직접 수정, 수정 전 상태 보관·복구 검토 |
| PowerPoint | 회사 레이아웃 기반 제목·overview·여러 이미지와 글상자 배치. 텍스트·이미지 교체 중심의 풍부하지만 과하지 않은 초안 |
| GitHub Enterprise | PR 생성까지. 병합 권한은 별도 미정 |
| GPU pool | 사내 CLI로 workload 생성·업로드·다운로드·모니터링. 현재 개발에서는 dummy 어댑터 제공 |
| Android | CMake·주로 arm64-v8a·실기기·NPU·ADB. Groovy Gradle, Kotlin·Java 혼용, 다중 모듈 |

- 도구별·작업공간별·기기별 허용 범위를 먼저 지정하고, 미지정 행동은 개별 승인받는다.
- 범위가 허용된 개발 작업의 파일 읽기·수정·빌드·테스트·프로젝트 의존성 설치는 자동 실행 가능하다.
- 시스템 전역 설치·설정 변경, 앱 데이터 초기화·기기 설정 변경은 확인한다.
- 지정한 개발 기기의 조회·앱 설치·교체·실행은 자동 허용 가능하다.
- 실기기는 Linux에 USB로 연결한다. Windows Desktop에서 Linux 실행 대상의 ADB·평가 도구를 제어한다.
- Office 문서를 사용자가 편집 중이면 저장과 작업 인계를 기다린다.
- 화면 점유가 필요한 작업은 제어를 넘겨받는다. 기본 10분의 시간 단위 허용과 사용자 제어 회수·일시정지를 제공하며 시간은 조정 가능하다.
- 별도 Windows 세션은 첫 버전에 전제하지 않는다.
- 직접 만든 Chrome 확장프로그램과 Native Messaging Rust bridge를 기본 연결 구조로 삼고, 사내 환경에서 호환성을 검증한다. 기본은 기존 SSO Chrome 프로필이며 전용 프로필도 선택할 수 있다.
- Agent는 작업에 연결된 새 탭을 사용한다. 기존 사용자 탭은 명시적으로 인계된 경우에만 사용하며, 사용자가 제어를 회수하면 해당 작업을 일시정지한다.
- 사이트 연결별로 프로필, 시작 URL 또는 Confluence space, 포함 페이지·경로, 제외 경로, 수집 주기와 허용 동작을 설정한다. 등록 범위 안에서 자동 탐색하며 범위를 넘으면 연결 추가를 제안한다. 전체 탭 상시 수집은 기본값이 아니다.
- 사용자에게 인계받은 탭, 초안 작성 탭, 로그인·MFA 대기 탭과 사용자가 고정한 탭은 유지한다. Agent가 만든 일회성 조회 탭은 원문·출처·결과 저장 후 정리한다. 모든 탭 유지 설정도 제공한다.
- 정기 수집 시 Chrome이 닫혀 있으면 다음 연결까지 보류하며 기본적으로 브라우저를 자동 실행하지 않는다. 인증 만료는 같은 원인에 대해 한 번 알리고 로그인 후 재개한다. 기존 수집 자료는 마지막 동기화 시각과 함께 계속 검색할 수 있다. 사용자 요청에 따른 브라우저 실행은 정기 수집과 별도 설정한다.

## 모델 변환과 NPU 평가

- 사용 SDK는 Qualcomm QAIRT, Samsung Exynos enntools, MediaTek NeuroPilot이다. 정확한 버전·지원 기기·설치 위치는 이후 확인한다.
- PyTorch에서 QAT를 수행하고 기본적으로 같은 원본 ONNX를 세 SDK에 전달한다. SDK별 세부 레이어 변경이 필요한 경우 원본과 별도의 파생 ONNX로 관리한다.
- 변환·빌드·기기 배포·실행·로그와 지표 분석을 연결한다. 변환기·기기·실행기·평가기의 교체 가능한 어댑터 구조를 적용한다.
- 세 SDK 변환 도구는 모두 Docker에서 실행한다. 실기기는 Linux에 USB로 연결하며 보통 한 대를 사용한다.
- 기존 변환 스크립트와 평가 프로그램은 사내에만 있어 현재 접근할 수 없다. 이후 에이전트에게 등록을 요청할 수 있도록 입력·출력·실행 환경·결과 해석을 등록하는 기능을 제공한다.
- 실기기 평가는 native 실행 파일, Android 앱, SDK 제공 평가 도구 등 여러 방식을 지원한다. 실제 프로그램과 SDK별 호출 계약은 사내 연결 후 등록·검증한다.
- 출력 차이의 기준은 원본 ONNX이며 PyTorch 출력이 아니다. SDK별 파생 ONNX를 만들더라도 최종 비교 기준을 조용히 변경하지 않는다.
- 출력 차이·정확도, 추론 지연, 초기화·모델 로딩 시간, 메모리, 전력·발열, 모델·산출물 크기를 평가 대상으로 한다. 측정 도구·데이터가 준비되지 않은 항목은 미측정으로 표시한다.

## Desktop과 편집 지원

- 하나의 창에서 대화 중심·편집 중심 배치를 전환한다.
- 과거 메시지에서 새 세션으로 분기하고, 메시지 수정 후 재요청은 원래 기록을 보존한 새 분기로 실행한다. 분기 시 포함할 대화·작업공간·모델 설정을 확인할 수 있다.
- 대화 분기는 현재 코드 상태를 사용한다. 당시 코드 상태를 복원하는 기능은 첫 버전에 필요하지 않다. 별도 작업용 worktree와 agent 변경 되돌리기는 유지한다.
- 하위 에이전트의 대화·실행 결과를 열어 볼 수 있고, 실패 작업은 완료된 도구 결과를 확인한 뒤 재개한다. 대화 분기가 이미 발생한 외부 변경을 취소하지 않는다.
- 파일 트리, 탭·분할 편집, 구문 강조, 자동완성, 정의·참조 탐색, 오류 진단, 통합 터미널, Git diff·부분 적용, 이미지·문서 미리보기를 제공한다.
- Agent가 읽은 버전과 적용 직전 파일 버전을 비교한다. 미저장 사용자 내용을 덮어쓰지 않으며, 겹치지 않는 변경은 병합을 시도하고 충돌은 diff로 제시한다.
- 사용자가 직접 편집 중인 파일의 agent 변경은 적용을 선택하도록 제시한다. 열려 있어도 미저장 변경이 없으면 자동 수정할 수 있으며 변경 표시·커서·화면 위치를 유지하도록 한다.
- Agent 변경 단위 복원과 사용자 편집 undo를 구분한다. 별도 worktree의 결과는 검토 후 통합한다.
- 언어 구현 순서는 Python·C/C++·CMake, TypeScript·Rust, Kotlin·Java·Gradle이다.
- 첫 사용 가능한 버전에 지정 언어의 편집 지원을 모두 갖춘다. Android Studio 전체 기능과 동일하다는 의미로 확대하지 않으며 언어별 기능을 실제 프로젝트로 검증한다.
- AGENTS.md, SKILL.md, MCP, 프로젝트 명령, 작업 preset을 첫 버전에 포함한다.
- 플러그인은 표·상태·폼·링크·diff 등 구조화된 결과를 제공하고 Rust가 렌더링한다. 새로운 전용 UI는 Rust 변경과 재시작으로 추가한다.
- 작업 내 질문·승인 카드, 응답 필요 항목 모음, 사이드바 작업 상태, 데스크톱 알림, 자기 개선 이력·평가·복원을 제공한다.
- UI는 한국어 기본에 영어 전환을 제공한다. 문서·메일은 한국어 중심이다. Codex Desktop과 가까운 화면을 요청한 후속 결정에 따라 중립 Light를 기본 테마로 하고 Solarized Light·다크 선택을 유지한다. 시스템 테마 연동은 후속 구현 항목이다.

## SSH와 Docker

- 판단·모델 호출은 로컬에서 수행한다. 로컬 PC가 꺼진 동안 원격 agent가 계속 판단할 필요는 없다.
- 원격 Ubuntu에 Python이 있고, 사용자 홈에 실행부를 배치할 수 있다고 가정한다. 컨테이너에도 Python이 있다고 가정한다.
- 기존 SSH config와 jump host를 지원한다. 인증·VPN의 구체 조건은 연결 환경에서 확인한다.
- 세션별 실행 대상과 기준 디렉토리를 관리한다. 상대경로 해석 기준과 접근 권한 범위를 구분한다.
- 주 실행 대상은 세션당 하나이며 다른 대상의 작업은 연결된 하위 작업으로 구성한다.
- 작업 실행 중 대상을 고정한다. 멈춘 상태에서 변경하면 지침·권한·환경을 다시 확인하고 이력을 남긴다.
- 원격 파일 트리·편집·검색·터미널·Git·worktree·LSP를 지원한다.
- SSH 종료 후 관리 대상 장기 작업은 유지·재접속 추적한다. 일반 터미널 세션 복구는 필수가 아니다.
- 미저장 편집은 로컬에 보존하고 재연결 시 원격 변경과 충돌을 확인한다.
- Docker 기존 컨테이너 연결과 새 컨테이너 생성을 지원한다. 프로젝트 템플릿에 이미지·마운트·작업 디렉토리·사용자·환경·포트·GPU·필요 실행 옵션을 저장한다.
- 컨테이너 수명은 세션과 독립적이다. 앱 생성과 기존 컨테이너를 구분하며 세션 종료 시 자동 삭제하지 않는다.
- 여러 세션이 컨테이너를 공유할 수 있다. 정지·삭제 시 관련 작업을 표시한다.
- 중요한 소스·결과는 지정한 호스트 마운트에 둔다. worktree와 Git 관리 경로의 컨테이너 접근을 함께 검증한다.
- 호스트 Python 프로젝트는 uv, 컨테이너는 기존 기본 환경을 사용한다.
- 로그·지표·작은 미리보기는 필요 시 가져오고, 대용량 파일은 선택 전송한다. 원격 자산 등록, 전송 크기·목적지 표시, 중단 후 재개·완료 검증을 제공한다.
- 서버 재부팅·컨테이너 삭제·재시작 이후 프로세스 생존은 SSH 재연결 보장과 구분한다.

## Linux 범위

GUI·편집·모델·agent·기억·Git·터미널·기본 브라우저 자동화를 지원하고 데이터 형식과 플러그인 계약을 공유한다. Windows 전용 Office·Outlook·사내 메신저 연결은 사용할 수 없는 기능으로 표시한다. Linux에서 Windows 기능을 원격 호출하는 기능은 첫 버전 범위가 아니다.
